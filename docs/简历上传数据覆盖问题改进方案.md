# 简历上传数据覆盖问题改进方案

## 一、问题分析

### 1.1 当前行为

通过分析后端代码（`internal/logic/studentlogic.go` 的 `UploadResume` 函数），发现以下问题：

**会覆盖的数据字段：**
- 基本信息：姓名、学历、专业、毕业年份
- 技能相关：技能列表、证书列表、软技能
- 经历相关：实习经历、项目经历
- 评估相关：完整度评分、竞争力评分
- 优化建议
- 简历文本内容

**不会丢失的数据：**
- 历史记录会完整保存在 `resume_parse_history` 表中
- 每次解析都会创建新记录，包含文件名、简历文本、解析结果等

### 1.2 潜在影响

**场景示例：**
1. 用户手动完善了个人资料（添加了额外的技能、证书、项目经历）
2. 用户上传新的简历
3. 系统用AI解析结果完全覆盖了手动完善的数据
4. 之前手动添加的数据永久丢失（除非查看历史记录）

**用户痛点：**
- 无法保留手动完善的补充信息
- 每次上传都需要重新添加额外信息
- 缺乏对数据更新的控制权
- 不确定哪些数据会被修改

**文件：** `internal/logic/studentlogic.go`
**函数：** `UploadResume`
**问题代码段（第12步）：**

## 二、改进方案

### 2.1 方案一：智能合并（推荐）

**核心思路：**
保留用户手动完善的数据，仅更新AI解析出的新信息。对于重复的字段，采用合并策略。

**合并策略：**

| 字段类型 | 合并策略 | 说明 |
|---------|---------|------|
| 姓名 | 优先使用AI解析 | 假设简历上的姓名是最准确的 |
| 学历/专业 | 优先使用AI解析 | 假设简历上的信息是最新的 |
| 技能列表 | 合并去重 | 保留手动添加的技能，添加AI解析的新技能 |
| 证书列表 | 合并去重 | 保留手动添加的证书，添加AI解析的新证书 |
| 软技能 | 保留手动 | 软技能较为主观，保留用户手动填写 |
| 实习经历 | 合并 | 添加AI解析的新经历 |
| 项目经历 | 合并 | 添加AI解析的新经历 |
| 完整度/竞争力 | 重新计算 | 基于合并后的数据重新计算 |

**优点：**
- 最大化保留用户数据
- 自动化程度高，用户无需干预
- 适合大多数使用场景

**缺点：**
- 可能产生冗余数据
- 用户可能不希望某些字段被更新
- 需要复杂的合并逻辑

**实现复杂度：** 中等

---

### 2.2 方案二：用户确认机制

**核心思路：**
上传简历前，展示AI解析结果与现有资料的对比，让用户选择更新哪些字段。

**UI 流程：**

```
用户选择简历文件
    ↓
前端预览AI解析结果（不保存）
    ↓
检查用户是否有现有资料
    ↓（有现有资料）
显示对比界面：
┌─────────────────────────────────────┐
│  简历解析结果 vs 现有资料          │
├──────────┬──────────┬──────────────┤
│ 字段     │ AI解析   │ 现有资料     │
├──────────┼──────────┼──────────────┤
│ 姓名     │ 张三     │ 张三         │ ✓ (相同)
│ 学历     │ 本科     │ 本科         │ ✓ (相同)
│ 技能     │ Go,Java  │ Go,Python    │ ⚠ (不同)
│ 证书     │ AWS      │ 无           │ + (新增)
└──────────┴──────────┴──────────────┘

请选择要更新的字段：
☑ 姓名
☑ 学历
☑ 技能列表（合并模式）
☑ 证书列表（合并模式）
□ 软技能（保留现有）

[取消] [仅保存到历史记录] [确认更新]
```

**优点：**
- 用户完全掌控数据更新
- 透明度高，用户了解每个变更
- 避免意外覆盖

**缺点：**
- 增加用户操作步骤
- UI 开发工作量较大
- 可能影响用户体验（操作繁琐）

**实现复杂度：** 高

---

### 2.3 方案三：版本管理与回滚

**核心思路：**
每次更新都创建快照，支持回滚到任意历史版本。

**数据结构设计：**

```sql
-- 学生资料版本表
CREATE TABLE student_profile_versions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    version_number INT NOT NULL,
    profile_data JSON NOT NULL,  -- 完整的profile数据
    source VARCHAR(50),          -- 'manual' 或 'resume_upload'
    resume_history_id BIGINT,    -- 关联的简历解析记录
    created_at INT NOT NULL,
    is_current BOOLEAN DEFAULT FALSE
);
```

**功能特性：**
1. 自动版本控制：每次修改创建新版本
2. 版本对比：可视化对比不同版本差异
3. 一键回滚：恢复到任意历史版本
4. 版本列表：显示所有版本的时间线和变更来源

**优点：**
- 数据安全性最高
- 用户可以随时回滚
- 完整的数据追溯能力

**缺点：**
- 存储成本增加
- 查询性能可能受影响
- 需要管理版本数量（定期清理旧版本）

**实现复杂度：** 中高

---

### 2.4 方案四：字段级别控制

**核心思路：**
在用户设置中提供字段更新策略，支持"自动"、"提示"、"不更新"三种模式。

**设置界面示例：**

```
简历上传更新策略
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

姓名：         [自动更新 ▾]
学历/专业：     [自动更新 ▾]
技能列表：     [智能合并 ▾]
证书列表：     [智能合并 ▾]
软技能：       [不更新 ▾]
实习经历：     [智能合并 ▾]
项目经历：     [智能合并 ▾]

策略说明：
• 自动更新：使用AI解析结果
• 智能合并：合并去重，保留现有数据
• 提示确认：上传前询问是否更新
• 不更新：保留现有数据

[保存设置]
```

**优点：**
- 灵活性高，满足不同用户需求
- 用户可自定义行为
- 一次设置，持续生效

**缺点：**
- 设置项较多，可能让用户困惑
- 需要良好的UI设计
- 需要额外的配置存储

**实现复杂度：** 中等

## 三、推荐方案组合

基于用户友好性和开发成本的平衡，推荐以下**分阶段实施方案**：

### 阶段一：智能合并（最小化MVP）
- 实现基础智能合并逻辑
- 重点保护技能、证书等列表类数据
- 基本姓名、学历等直接更新
- **预期效果**：减少数据丢失，保护用户手动添加的内容

### 阶段二：简化确认机制
- 在智能合并基础上，添加简单的确认对话框
- 仅在检测到"重要数据差异"时提示
- 提供"覆盖"和"保留现有"两个选项
- **预期效果**：在重要变更时保护用户数据

### 阶段三：版本管理
- 实现版本快照和回滚功能
- 提供版本历史查看
- **预期效果**：提供数据安全保障

### 阶段四：高级控制
- 添加字段级别的更新策略设置
- 提供更精细的控制选项
- **预期效果**：满足高级用户需求

```go
func mergeSkills(existing []Skill, new []Skill) []Skill {
    skillMap := make(map[string]Skill)
    // 添加现有技能
    for _, skill := range existing {
        skillMap[skill.Name] = skill
    }
    // 合并新技能（保留更高的掌握程度）
    for _, skill := range new {
        if existingSkill, ok := skillMap[skill.Name]; ok {
            // 保留更高的评分
            if skill.Level > existingSkill.Level {
                skillMap[skill.Name] = skill
            }
        } else {
            skillMap[skill.Name] = skill
        }
    }
    // 转换为切片
    result := make([]Skill, 0, len(skillMap))
    for _, skill := range skillMap {
        result = append(result, skill)
    }
    return result
}
```

2. **证书合并算法**
```go
func mergeCertificates(existing []Certificate, new []Certificate) []Certificate {
    certMap := make(map[string]Certificate)
    // 使用"名称+等级"作为唯一标识
    for _, cert := range existing {
        key := fmt.Sprintf("%s-%s", cert.Name, cert.Level)
        certMap[key] = cert
    }
    for _, cert := range new {
        key := fmt.Sprintf("%s-%s", cert.Name, cert.Level)
        if _, ok := certMap[key]; !ok {
            certMap[key] = cert
        }
    }
    result := make([]Certificate, 0, len(certMap))
    for _, cert := range certMap {
        result = append(result, cert)
    }
    return result
}
```
