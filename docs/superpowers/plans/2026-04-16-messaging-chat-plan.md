# 站内信与聊天室实现计划

> 目标：在不影响现有站内信能力的前提下，补齐教师端和学生端的实时聊天室、消息中心页面和自动建会话能力。

## 已确认设计

- 站内信继续复用现有 `messages` 表与路由。
- 聊天室使用 `chat_groups`、`chat_group_members`、`chat_messages`。
- 实时推送采用 SSE。
- 聊天室仅支持一对一 direct 会话。
- 学生入校后自动为同校教师建会话，且必须幂等。

## Phase 1: 后端聊天室

### 1. 数据层整理

- 确认 `career.go` 中聊天室表定义与设计一致。
- 如字段缺失，补齐 `chat_group_members.last_read_at`、`chat_messages.sender_name` 等必要字段。
- 补充索引，保证会话列表和消息历史查询可用。

### 2. 聊天室 API

- 完成 `/api/v1/chat/groups` 会话列表和创建接口。
- 完成 `/api/v1/chat/groups/:id/messages` 消息历史与发送接口。
- 完成 `/api/v1/chat/groups/:id/members` 成员接口。
- 完成 `/api/v1/chat/groups/:id/read` 已读接口。
- 完成 `/api/v1/chat/groups/:id/stream` SSE 推送接口。

### 3. 权限与幂等

- 校验当前用户必须是会话成员。
- 创建会话时检查是否已存在相同 direct 会话，避免重复。
- 发消息后更新群组 `updated_at`，供列表排序。

### 4. 自动建会话

- 在学生加入学校成功后，查出同校教师。
- 为每位教师生成 direct 会话。
- 写入双方成员记录。
- 保证重复调用时不会创建重复会话。

## Phase 2: 教师端前端

### 1. 页面与路由

- 新增教师端消息中心页，建议路径为 `/teacher/messages`。
- 在教师端导航中增加消息入口和未读数显示

### 2. 页面结构

- 使用 Tabs 分为“站内信”和“聊天室”。
- 站内信：列表、详情、发送弹窗。
- 聊天室：左侧会话列表，右侧聊天窗口。

### 3. 交互

- 会话切换时重新加载历史消息。
- 进入会话后自动标记已读。
- SSE 收到新消息时刷新当前会话和列表摘要。

## Phase 3: 学生端前端

### 1. 页面与路由

- 新增学生端消息中心页，建议放入主导航或个人中心入口。
- 在学生端导航中增加消息入口和未读数显示。

### 2. 页面结构

- 使用 Tabs 分为“站内信”和“聊天室”。
- 站内信：收件箱、详情、已读状态。
- 聊天室：会话列表和对话窗口。

### 3. 交互

- 默认展示最近活跃会话。
- 支持回车发送、Shift+Enter 换行。
- 发送失败保留草稿并提示重试。
- SSE 断开后自动重连并补拉消息。

## Phase 4: 验证

- 验证教师端、学生端都能看到消息入口。
- 验证同一会话在两端实时收发正常。
- 验证消息历史刷新后仍然正确。
- 验证未读数和已读状态更新正确。
- 验证站内信现有能力不受影响。

## 建议执行顺序

1. 先完成后端聊天室和 SSE。
2. 再接入学生入校自动建会话。
3. 然后做教师端消息中心。
4. 再做学生端消息中心。
5. 最后补体验细节和未读数优化。
