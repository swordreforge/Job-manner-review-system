# 智能岗位评价与一体化招聘管理平台—八章简化版大纲（实现对齐版）

> 说明：本稿已按当前仓库实现能力重写。只保留已落地模块作为“现状能力”，未实现项仅放入“边界/后续”，避免误写为已交付功能。

---

## 第一章 项目概况

### 1.1 项目定位（当前版本）
说明：当前系统本质是“学生职业规划、岗位匹配、教师协同管理”平台，而非完整企业招聘管理系统。  
可行点：定位与现有前后端模块一致（学生、岗位、匹配、报告、教师端、消息、面试、霍兰德测评）。  
商业化落点：可先作为院校职业发展与就业指导平台商业化落地。

### 1.2 当前已实现能力总览
说明：已实现账号认证、学生档案、简历解析、岗位库、匹配推荐、职业报告、面试模拟、教师管理与消息沟通。  
可行点：能力都有对应 API 与页面入口，可演示、可验收。  
商业化落点：可按“基础功能包与增值 AI 功能包”打包销售。

### 1.3 当前未实现边界（必须明确）
说明：企业 HR 端招聘流程（发布-筛选-录用-offer-入职）尚未完整实现，不应写成已落地。  
可行点：在方案中将其标注为“后续扩展方向”，不计入当前交付承诺。  
商业化落点：避免销售超卖，降低交付与信誉风险。

### 1.4 目标用户（按现有功能）
说明：核心用户为学生与教师，院校管理者为次级管理角色。  
可行点：前端已有学生端与教师端路由及对应功能页。  
商业化落点：先聚焦 B 端院校采购，再服务 C 端学生使用。

### 1.5 核心价值
说明：学生侧提升职业认知与行动路径清晰度；教师侧提升辅导效率与风险预警能力。  
可行点：通过测评、匹配、报告、消息与预警形成业务闭环。  
商业化落点：可用“辅导效率提升、学生活跃提升、任务完成率提升”作为价值指标。

### 1.6 版本边界定义
说明：区分“已实现（可交付）”“在研（可试点）”“规划（不承诺）”。  
可行点：在章节内逐项标注状态，避免概念混淆。  
商业化落点：增强合同范围清晰度，控制实施成本。

## 第二章 需求与场景分析

### 2.1 学生侧真实问题
说明：职业方向模糊、岗位要求不清、行动计划不可执行。  
可行点：已有霍兰德测评、岗位匹配、报告生成功能对应解决。  
商业化落点：学生端体验是院校续费关键抓手。

### 2.2 教师侧真实问题
说明：学生数量多、个体差异大、预警与跟踪成本高。  
可行点：已有教师学生列表、任务查看、告警处理、消息沟通。  
商业化落点：教师效率提升可直接转化为院校采购理由。

### 2.3 院校管理侧问题
说明：需要可视化与可复盘的过程数据，不只看结果。  
可行点：系统沉淀档案、匹配结果、报告历史、面试历史与消息数据。  
商业化落点：为管理汇报与评估提供数据基础。

### 2.4 场景闭环（已落地）
说明：学生建档/上传简历 → 岗位匹配 → 报告生成/润色 → 教师跟踪辅导。  
可行点：主链路在 API 与前端页面均可串通。  
商业化落点：闭环可直接用于试点验收。

### 2.5 场景补强（已落地）
说明：面试模拟与霍兰德测评用于补充能力画像与职业倾向判断。  
可行点：已提供测评题库、测评历史、面试会话与报告能力。  
商业化落点：形成差异化卖点，提高客单价上限。

### 2.6 不纳入当前承诺的场景
说明：企业岗位审批流、校企双向协同录用流程当前未完整交付。  
可行点：仅列为后续路线，不放入当前验收指标。  
商业化落点：承诺可交付范围，避免项目亏损。

## 第三章 产品方案（实现映射）

### 3.1 用户与认证模块
说明：支持注册、登录、用户信息维护、头像上传、密码修改、账号注销。  
可行点：后端已有 user 路由与逻辑，前端已集成鉴权流程。  
商业化落点：账号体系稳定是院校上线基础门槛。

### 3.2 学生档案模块
说明：支持学生档案创建、更新、查询、列表、删除。  
可行点：已有 students CRUD API 与学生页面。  
商业化落点：档案数据是后续所有增值功能输入。

### 3.3 简历解析与历史模块
说明：支持简历上传生成画像，并可查看/删除解析历史。  
可行点：已有 resume 上传、history 列表与详情接口。  
商业化落点：可作为“AI 档案增强”增值能力收费。

### 3.4 岗位库模块
说明：支持岗位 CRUD、岗位筛选检索、AI 岗位画像生成。  
可行点：已有 jobs 与 jobs/generate 接口及前端岗位页。  
商业化落点：岗位库质量决定匹配效果，是核心体验来源。

### 3.5 匹配推荐模块
说明：支持单岗位匹配、多岗位匹配、推荐岗位与匹配评分。  
可行点：已有 match 相关全套接口。  
商业化落点：可用匹配准确度与推荐点击率作为价值指标。

### 3.6 报告模块
说明：支持报告生成、流式生成、编辑、润色、导出、完整性检查与我的报告。  
可行点：已有 reports 全链路接口与页面交互。  
商业化落点：报告可直接作为教学交付成果与服务证明。

### 3.7 测评与面试模块
说明：霍兰德测评支持答题、结果、历史；面试支持会话、历史、报告、结束与删除。  
可行点：后端 interview/holland 路由齐全，前端已有对应页面。  
商业化落点：形成“测评、模拟、反馈”高黏性能力。

### 3.8 教师协同与消息模块
说明：支持教师注册、邀请码、学生查看、任务查看、告警处理与双端消息沟通。  
可行点：已有 teachers 与 chat/messages 接口、教师端页面。  
商业化落点：教师协同能力是院校付费核心。

### 3.9 产品边界声明
说明：当前不宣称“企业全流程招聘管理”已上线。  
可行点：将“企业端完整流程”放入路线图章节。  
商业化落点：降低交付冲突与后续返工成本。

## 第四章 技术方案（基于现有架构）

### 4.1 系统架构
说明：Go 后端 API、React/Vite 前端、MySQL、Redis 的多模块架构。  
可行点：仓库已有完整服务启动与配置文件。  
商业化落点：成熟技术栈降低维护成本与团队风险。

### 4.2 服务组成
说明：核心后端与前端已稳定，语音服务与教师服务作为配套服务存在。  
可行点：有统一服务管理脚本和日志目录。  
商业化落点：可按能力模块化部署，控制实施成本。

可行点：配置可通过 YAML 管理，逻辑已在对应接口落地。

### 4.4 实时交互机制

可行点：前后端均有流式处理逻辑。  
商业化落点：提升用户感知速度和高级感。

### 4.5 数据与安全
说明：已有鉴权中间件、用户权限、基础健康检查与日志。  
可行点：关键用户操作均通过受保护接口访问。

### 4.6 当前技术边界
说明：当前文档不宣称已实现多租户 SaaS 计费系统、复杂 SLA 平台化运维。  
可行点：仅描述仓库中可验证能力。  
商业化落点：技术承诺与交付能力一致，降低售后风险。

## 第五章 商业模式与变现路径（当前可执行）

### 5.1 当前可售卖对象
说明：以院校职业发展中心/二级学院为主要采购对象。  
可行点：功能重点已覆盖学生与教师协同。  
商业化落点：B 端付费、C 端使用的模式可直接落地。

### 5.2 当前可交付产品包
说明：基础包（账号、档案、岗位、匹配）与增强包（报告、测评、面试、教师告警、消息）。  
可行点：每个包都可映射到已实现模块。  
商业化落点：分层报价提升签约成功率。

### 5.3 当前可执行收费方式
说明：按年服务费与实施服务费（不引入未实现的复杂自动计费体系）。  
可行点：结合当前交付方式可直接执行。  
商业化落点：回款路径清晰，可控性高。

### 5.4 价值证明指标（可验证）
说明：学生档案完善率、报告生成量、教师处理告警时效、消息响应时效。  
可行点：这些数据在系统中可采集与统计。  
商业化落点：作为续费与增购谈判依据。

### 5.5 试点转化路径
说明：先在单院校/单学院试点，再横向复制。  
可行点：现有能力足够支持小范围试点闭环。  
商业化落点：以低风险试点换取正式采购。

### 5.6 商业边界控制
说明：当前不承诺“企业全流程招聘管理平台交付”。  
可行点：合同中明确“已实现模块清单”。  
商业化落点：降低过度承诺导致的赔付风险。

## 第七章 财务与风险（现阶段口径）

### 7.1 成本构成（当前）
说明：研发维护成本、部署运维成本、AI 调用成本、实施培训成本。  
可行点：均与当前系统形态直接相关。  
商业化落点：成本口径真实，便于报价与毛利测算。

### 7.2 收入构成（当前）
说明：年度服务费、实施费、增强功能包费用。  
可行点：不依赖未实现计费系统即可执行。  
商业化落点：收入模型简单、可回款。

### 7.3 风险一：功能承诺超范围
说明：将规划功能当作已上线销售会导致交付风险。  
可行点：统一“实现清单”作为售前标准材料。  
商业化落点：减少项目亏损与信誉损失。

### 7.4 风险二：AI 成本波动
说明：报告/匹配/面试等 AI 调用量提升会增加成本。  
可行点：按功能包与调用额度做管理。  
商业化落点：避免毛利被 AI 成本侵蚀。

### 7.5 风险三：使用率不足
说明：若教师端与学生端活跃不足，续费能力下降。  
可行点：通过运营指标和培训机制提高使用深度。  
商业化落点：提升续费率与长期收入稳定性。

### 7.6 风险四：技术稳定性
说明：多服务运行与长耗时请求对稳定性有要求。  
可行点：使用现有健康检查、日志与超时控制。  
商业化落点：稳定体验是长期合作基础。

### 附录C 商业化指标清单（当前版本）
