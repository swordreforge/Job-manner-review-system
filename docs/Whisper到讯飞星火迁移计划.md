# Whisper 到讯飞星火语音识别迁移计划

## 📋 迁移概述

### 迁移目标
- 将 OpenAI Whisper 语音识别迁移到讯飞星火中英识别大模型
- 提升语音识别准确率和速度
- 支持更多方言和语种（中文、英文及 202 种方言）
- 保持前端接口不变，实现无缝迁移

### 当前架构分析

**Whisper 实现方式：**
- 前端直接调用 Python FastAPI 服务（`http://localhost:8000/transcribe`）
- Whisper 服务部署在 `whisper-20250625` 目录
- 前端通过 MediaRecorder 录音，发送音频文件到 Whisper 服务
- 返回识别文本到前端输入框

**讯飞星火特性：**
- 使用 WebSocket 协议（ws://iat.xf-yun.com/v1）
- 支持实时流式音频传输
- 需要鉴权（HMAC-SHA256 签名）
- 支持中文、英文及 202 种方言
- 单次识别最长 60 秒
- 基于大模型训练，识别上限更高

### 技术对比

| 特性 | Whisper | 讯飞星火 |
|------|---------|----------|
| 识别准确率 | 中等 | 高（大模型） |
| 识别速度 | 2-3秒/分钟 | 1-2秒/分钟 |
| 方言支持 | 有限 | 202种方言 |
| 部署方式 | 本地 | 云端 API |
| 资源占用 | 高（1-2GB 内存） | 低（仅网络） |
| 成本 | 免费 | 按调用次数计费 |
| 实时性 | 较低 | 高（流式） |
| 网络依赖 | 无 | 依赖网络 |

## 🚀 迁移方案

### 技术选型

**方案 A：替换现有 Whisper 服务**（推荐）
- 修改 `whisper-20250625/web_app.py`
- 保持 `/transcribe` 接口不变
- 内部调用讯飞星火 API
- 对前端透明，无需修改前端代码

**方案 B：新建独立服务**
- 创建 `xunfei-asr-service` 目录
- 提供新的 WebSocket 接口
- 前端需要修改调用方式

**推荐方案 A，原因：**
- 改动最小，兼容性好
- 易于回退
- 可以并行测试两种方案

## ⚠️ 注意事项

### 网络依赖
- 讯飞星火需要稳定的网络连接
- 建议添加超时和重试机制
- 网络异常时的降级方案

### 成本控制
- 监控 API 调用次数
- 实现音频预处理，减少无效调用
- 设置调用频率限制

### 数据隐私
- 音频数据会上传到讯飞服务器
- 确保符合隐私政策要求
- 提供数据删除选项

### 兼容性
- 保持接口不变，便于回退
- 保留 Whisper 服务作为备选
- 支持双服务并行运行

### 音频格式
- 讯飞星火支持 PCM（raw）和 MP3
- 需要确保前端发送正确的格式
- 采样率：16000Hz 或 8000Hz
- 位深：16bit
- 声道：单声道

## 🔄 回滚方案

如果迁移后出现问题，可以快速回滚：

### 回滚步骤

1. **停止讯飞星火服务**
   ```bash
   pkill -f web_app.py
   ```

2. **恢复 Whisper 服务**
   ```bash
   cd whisper-20250625
   git checkout HEAD~1 -- .
   pip install -r requirements.txt
   python web_app.py
   ```

3. **验证回滚**
   ```bash
   curl http://localhost:8000/health
   ```
